# Handoff: Milestone 2 — Design and Survey

The local stack is running: LimeSurvey 6.17.18 and MariaDB via `docker compose up -d` in `~/Projects/hotelSurvey`, with the survey served at `http://hotelsurvey.localhost` through the shared Caddy in `~/docker-infrastructure/caddy`. Your job is to build the branded, bilingual guest survey described in PRD §4.1 (FR-02 to FR-05), §5.2–5.5 and Milestone 2 in §8, and nothing else. Start by reading `AGENTS.md`, `docs/decisions.md` (section 1 is resolved and binding), and the PRD sections above. The child theme goes in `limesurvey/themes/hotel-classic/`, which is already mounted into the container at `upload/themes/survey/hotel-classic`. It must extend the stock `vanilla` theme through `config.xml`, and the design tokens in `css/tokens.css` must be the only source of colours, type and spacing. Do not edit LimeSurvey core files or LimeSurvey's own database tables; survey content is created through the LimeSurvey admin at `http://hotelsurvey.localhost/index.php/admin`, and any changes that must live in code go in the theme directory. The survey needs nine questions exactly as in PRD §4.1 FR-04: six 1–5 ratings, a 0–10 recommendation question, and two optional text fields, with German and English translations of every string, a welcome screen with the suggested message and an estimated completion time, a progress indicator, back and continue navigation, a thank-you screen with the suggested message, and anonymous-by-default collection. Do not add a room token or room field yet; that is Milestone 3. Leave the survey's language fixed for the whole session. Milestone 2 is done when the branded survey works in both languages on a phone-sized viewport, every required question is validated, optional questions can be skipped, and the thank-you screen appears after submission. Use `docker compose exec limesurvey` and the Caddy URL to check your work, and run `./scripts/validate.sh` before reporting back. Do not commit or push anything. Open items that are not yours to decide are listed in section 2 of `docs/decisions.md`; use the placeholder brand in `docs/brand.md` (Bagh-e Pardis / Paradise Garden Hotel, with the wordmark and tagline described there) for the welcome and thank-you screens. It is a development placeholder, so mark it clearly as such in any shared preview, and do not treat it as cleared for production. Report which of the Milestone 2 tasks in PRD §8 are complete, which are not, and anything that needed a decision outside this brief.
